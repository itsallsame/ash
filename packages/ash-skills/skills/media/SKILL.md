# 照片、视频和相机

这些能力在主人的手机上（`device:<手机的 id>`，id 从上下文的设备列表拿）。照片是主人的私人文件：用得有目的、说清看了什么、不外传。

## 五个能力

| 能力 | 做什么 | 要点 |
|---|---|---|
| `media.albums {type?}` | 有哪些相册（文件夹）、各有多少、最新一张的时间 | 先看它，再决定翻哪个相册 |
| `media.list` | 按条件列出，最新在前 | `type`（`image`/`video`/`audio`/`any`）、`since_ms`/`until_ms`（拍摄时间，毫秒）、`album`、`name`（文件名含）、`order`、`limit`（1–100，默认 30）、`offset`；翻页用返回的 `next_offset`；`with_location: true` 才带拍摄地点，慢，没必要不开 |
| `media.read {id, max_size?, copy?}` | 打开一项（`id` 来自 `media.list`） | 照片变成你能看的图（长边最多 `max_size`，256–2048，默认 1280），并在工作区留一份 JPEG（`path`）；视频给一帧加一个路径；`copy: true` 才把原图拷一份给你 |
| `media.save {path 或 data, name?, mime_type?, album?}` | 把图片或视频存进相册 | `path` 是你环境里的文件（如 `/root/work/out.jpg`）或 `/sdcard/...`；`data` 是 base64，约 10 MB 以内；默认存到 `Pictures/Ash`；只收图片和视频 |
| `camera.capture {reason?, timeout_s?, max_size?}` | **请主人拍一张** | 手机的系统相机会打开，主人按快门；返回照片（图和工作区里的路径），**不会进相册**，要进相册再 `media.save`。`reason` 写一句短中文说明拍什么，Ash 在后台时它会出现在通知里。`timeout_s` 15–150，默认 120 |

没有移动、改名、删除照片的能力。需要主人先在手机的「照片、视频和文件」权限里打开；没开时结果是 `permission_denied`，用 `config.permission.request {name: "photos"}` 打开授权页，让他自己去开，不要反复重试。

## 场景一：看一张照片、找一张照片

主人说「上周在杭州拍的那张西湖」：`media.list {type: "image", since_ms, until_ms}`，先用文件名、相册、时间缩小；候选很多时不要一张张都 `media.read`，用小图（`max_size: 512`）挑几张看，找到再用大图。看完告诉他是哪一张（时间、相册），不要把整个列表倒给他。

## 场景二：整理相册

先看，后动手，并且默认只给方案。

1. `media.albums` 看全貌；对最大的几个相册用 `media.list` 分页统计（截图多少、几月最多、有没有大量重复的名字或大小）。需要判断内容时每类抽样几张看。
2. 回主人一个**方案**：哪些是截图、哪些像是重复、可以怎么分组，数量各多少。方案是文字，不改动任何文件。
3. 主人明确说要动，才动：没有专门的移动和删除能力，只能经 `/sdcard` 路径用命令；先拿一小批试，再核对相册里的变化（相册可能不会立刻刷新），再继续；**删除永远要他明确说要删哪些**，并告诉他不可恢复。
4. 做完汇报：动了几个、在哪里、哪些没动。

## 场景三：请主人拍一张，再继续

1. 先用一句话告诉他要拍什么、为什么（「请拍一下药盒上的有效期，我帮你记下」），再调 `camera.capture {reason: "拍药盒上的有效期"}`。
2. 它会一直等到主人拍完或超时（最长 150 秒）。超过十几秒会先返回回执（`status: accepted`），用 `await_result` 收，不要重复调用，否则会重复请他拍。
3. 结果是 `cancelled`（主人关了相机）：不要再催，问他要不要换个办法；`timeout`：说一声「没等到照片」，等他再说。
4. 拿到照片：照常看，按需要处理。要留存才 `media.save`，并告诉他存到了哪个相册。

## 场景四：存回相册

处理好的图放在你的工作区，然后 `media.save {path: "/root/work/out.jpg", name: "收据-0930.jpg", album: "Ash"}`。成功返回 `uri` 和 `folder`，对主人说存到了「Pictures/Ash」。失败信息里有原因（不是文件、不是图片、没权限），照实说。

## 隐私与审批

- 读（列表、相册、看照片）直接执行；存进相册是写，裁判可能放行也可能问主人；相机由主人亲手按快门，相机界面本身就是同意，不另弹卡。
- 不把照片内容发给别人或传到别的服务；回复里只说必要的，不转述无关的人脸、证件号、位置。
- 拍摄地点只在确实需要时才读（`with_location`）。
- 不在主人没要求时翻相册；做了就说明用途。

## 好的样子

主人说「把上个月的收据照片看一下，帮我把金额加起来」。`media.albums` 看到 Camera 和 Screenshots；对两个相册分别 `media.list {type: "image", since_ms, until_ms, album}`，共 12 张；每张 `media.read {id, max_size: 768}` 读金额，不拷原图。回复一张小表：日期、金额、是哪一张（时间和相册），总计 842.50 元；末尾说「有 2 张看不清，列在下面，请你确认」。照片没有离开手机，也没有改动任何一张。

## 常见错误

- 一上来就把几十张都 `media.read`，又慢又费。
- 没问就整理、移动或删除。
- 以为 `camera.capture` 的照片已经在相册里。
- 超时或取消后连续再请主人拍。
- 权限没开时反复调用而不是发权限卡。

## 怎么核对

找照片：告诉主人你选的是哪一张（时间、相册）。存图：看到 `media.save` 成功的返回再说存好了。整理：汇报的数量和你实际动过的数量一致。
