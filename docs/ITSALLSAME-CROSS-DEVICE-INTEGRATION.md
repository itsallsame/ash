# itsallsame 作为消费者的最小跨端协作设计

2026-10-09。仅研究与设计；未修改业务代码、安装连接器、发起手机操作或验证真机连接。

## 产品边界

业务继续发生在用户正在使用的 Codex / itsallsame 会话中。该会话决定需要什么帮助、如何解释结果以及下一步业务动作。Ash 提供通用的跨端协作能力：发现目标、传递必要上下文、接收请求、返回材料与结果。手机也可以主动发起请求；任务拆分是调用方可选行为。

Ash 保存协作记录，不维护视频制作阶段、Mission Case 状态或发布工作流。现有业务系统的对象只作为有来源的引用。第一版按请求保存必要上下文；未来可以积累用户授权的跨请求背景，但不能把局部摘要视作完整个人记忆。

## 首个验证场景

Codex 在 itsallsame 中需要一张手机上的创作者后台截图。它向用户的手机请求“提供所选账号页面的截图，并保留采集时间与用户说明”。手机由用户选择截图并提交；电脑取得文件后，由原会话按现有 Mission 规则识别、预览和确认。

第一版允许人工在手机选择材料，不要求自动操作所有 App。手机传回截图只代表局部请求完成，不能宣称指标已导入。账号归属、数据解释、业务确认和写入仍由原流程负责。相同协作结构以后可以用于照片、链接、文件或针对某版本的反馈，无需在 Ash 中增加指标或视频专用阶段。

## 目标交互

1. 当前 Codex 会话发现已配对手机及其可用能力，提交一次材料请求。
2. 提交立即返回 request_id；用户看到“已请求手机提供截图”。会话可以继续其他工作或结束本轮。
3. 手机显示请求来自哪个客户端、用途、需要的材料和授权范围。用户提交选定文件或回复无法提供。
4. 结果关联同一 request_id，包含明确选取的附件、来源、时间和说明。
5. 原会话再次查询时取得结果及本机可读的文件，按已有业务规则继续。

暂不承诺客户端在空闲时被自动唤醒或向既有聊天强行注入新消息。首个闭环允许用户回到原会话说“取回手机结果”。手机主动发送信息时，也先进入指定接收方的可领取记录；自动启动、续接会话取决于对应连接器已验证的能力。

## 通用契约草案（拟议，尚未实现）

对外适配器提供 discover、submit、get_result 三项基本操作；后续增加 cancel。可以由支持工具接入的客户端通过 MCP 使用，也可提供 CLI。是否能在当前 Codex Desktop 配置并调用，需单独做接入验证；不以另起运行器代替原会话而不告知用户。

请求包含：request_id、幂等键、发起客户端和会话引用、目标能力、任务说明、必要背景、期望输出、授权范围、到期时间。客户端身份由可信连接器赋予，不能由模型填写后直接信任。会话引用用于返回定位，不代表系统可读取或控制该会话。

结果包含：request_id、处理状态、结果摘要、附件引用、来源时间、未完成部分和错误原因。附件还需有名称、类型、字节数、内容摘要及接收端可读取的凭据或位置。手机本地路径不能充当已交付文件。

上下文中的来源内容与用户授权分开保存：网页、图片内文字或别的 Agent 的总结都不能自行扩大执行权限。模型摘要注明来源、时间及缺失项，原材料可回查。

## 最小状态与恢复

使用已有路由状态映射为用户能理解的“已接收、处理中、等待用户、已返回、失败、过期、结果未知”；这些是局部协作状态。单独标明结果已被发起端领取，不把领取等同于业务验收。

- 请求在报告“已接收”前须可靠记录；同一幂等键重试不得生成第二次执行。
- 电脑结束本轮或重启后可以按同一身份与 request_id 取回结果；接入实现不能依赖原 turn 的内存 Promise。
- 手机离线应明确显示待处理或无法投递；是否等待及等待多久由请求期限决定，不能假定当前路由已支持任意时长离线队列。
- 执行动作后丢失回执，应报告结果未知；读取证据或人工核实后再决定重试。
- 取消不保证撤销已完成动作。过期、撤销授权后的迟到结果须标记，不自动触发下一项业务动作。

## 技术接入边界

建议由电脑本地适配器承接原客户端调用，经过配对身份和网关访问手机侧授权能力。复用现有成员发现、消息路由、ledger、幂等键和回复关联；新增部分首先限定在原客户端入口、限定身份的结果查询和附件交付。

Core MCP 的本地身份及 x-ash-token 不能直接改成公网入口或交给模型跨端转发。须审查网关到手机的身份映射和现有授权能否表达该调用；不能把外部客户端伪装成本地 owner。get_result 只允许读取该身份有权访问的请求。

附件传输方式还未选型。首个截图闭环应核对现有传输限制和授权后，决定复用通道还是增加短期附件传输；需要明确大小限制、保存位置、过期删除及领取失败行为。暂不扩展为大型视频文件同步。

## 设计验收与下一次研究

先在代码层整理“能力 / 当前接口 / 缺口 / 最小改动”的连接器清单，再决定是否进入开发。实际验证留待用户明确允许后进行。

未来最小验收：从原 Codex 会话提交请求；手机人工选图并返回；结束一轮后能再次领取；断线重试不重复请求；文件内容可核对；请求无法完成时原会话能看到原因；其他身份不能领取附件。最后由 itsallsame 自己继续处理，Ash 不新增任何内容生产业务对象。

这一闭环验证跨端局部协作的价值，不能证明任意 App 自动化、所有客户端续接、全量上下文同步或通用个人 Agent 已经成立。
