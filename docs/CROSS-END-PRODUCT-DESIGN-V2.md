# Ash 跨端协作产品设计 v0.6

2026-10-12 更新 · 产品设计；实现与真机验收以开发记录为准。

技术方案见[多端协作技术架构 v0.2](CROSS-END-TECHNICAL-ARCHITECTURE.md)。

依据：[业务、产品、技术五轮对垒](PRODUCT-DESIGN-DEBATE-2026-10-09.md)、用户新增的手机发起视频制作场景，以及后续 Codex 消息读取和运行中追加的验证。本文作为当前产品设计主稿；早期个人上下文稿保留为探索记录。

## 0. 首要原则：从最简单开始

依据用户 2026-10-11 的明确要求：**默认不加；先交付完成当前任务的最小产品，有真实需要时再增加。** 本原则适用于后续产品、交互、架构和开发，也适用于审减已有功能。与下文旧方案的常驻展示要求冲突时，以本节为准；原首阶段能力与必要授权、正确性要求保留。

- 会话页默认只有返回、标题、消息、输入框、发送。低频操作按需打开；运行说明、角色重复标签、技术状态、缓存配额和成功回执不常驻。
- 新增按钮、文字、字段、设置、步骤或模块，必须说明它解决哪个已经出现的用户问题，以及为什么现有流程不足。没有具体问题就暂不添加，不能以“以后可能用到”为理由。
- 先删除和合并，再考虑折叠。确需保留的低频内容才放进更多或详情，不能把无用内容全部藏起来当作简化。
- 使用已知、有效且已授权的默认值；只有歧义影响实际目标或缺少必要授权时才让用户选择。同一信息不重复确认。
- 状态只在影响下一步操作时出现。错误用一句话说明问题并提供必要行动；真实未知不能冒充已发送、运行中或已完成。投递与恢复事实保存在内部，不要求用户学习它们。
- 后台读取和状态更新不得打断输入、移动光标或覆盖中文组合输入。
- 每步验收同时看能否完成任务、用户操作是否更少、界面是否增加了无关内容。简单是验收标准，不靠测试数量或设置完整度代替。

当前最小基线：选择电脑 → 选择会话 → 看消息 / 发消息。新建会话只收集必要项目、标题和要求；材料按当前明确需求接入。跨端扩展保留所需契约，尚无场景的适配器、管理台和通用工作流不提前建设。

## 1. 产品承诺

让同一个用户在任何一个已接入的端，找到已有工作、发起新工作、补充材料、回答问题，并把结果带回自己正在使用的入口。连接对象可以是手机、桌面 AI 客户端或服务器 Agent。Ash 手机端是入口之一，连接与上下文能力也可供其他端调用。

核心价值是跨设备、跨应用、跨时间保留足够的上下文，让下一位参与者能够开始工作。允许只掌握局部信息，允许用户手动补充，不承诺全量历史读取或无缝会话迁移。

产品有两部分：用户直接使用的手机协作入口，以及对接已有工具的连接能力。既有客户端继续拥有自己的会话和执行环境；具体业务由原来的项目、Skill 与工具处理。产品架构覆盖 Windows、macOS、手机和云端的异构参与者。首次聚焦手机 Ash 与一台电脑上的 Codex，不以覆盖所有 Agent 为首版目标。下文 Codex 场景是首个适配实例；第 15–19 节定义多端扩展契约。

## 2. 三种明确意图

| 意图 | 常见表达 | 产品动作 |
| --- | --- | --- |
| 发起新工作 | 用这个视频做一条我们的产品视频 | 选择目标项目，创建并关联新会话，发送请求 |
| 继续已有工作 | 把这张图用到刚才那条视频里 | 定位已有会话，补充要求或材料 |
| 只保存信息 | 先收藏，回头再看 | 保存来源和说明，不启动执行 |

只打开系统分享面板不构成执行指令。分享后有明确制作要求时可直接提交，不机械增加一次批准。已明确“上线后执行”的请求可以等待电脑；仅收藏的材料永远不能因为电脑上线而自动开始工作。

“稍后提醒我”和“电脑上线后自动执行”是不同意图，不能混用。首版不额外引入日程系统。

## 3. 场景 A：手机分享抖音内容，新建制作会话

**2026-10-11 最小交付路径：** 系统分享含 HTTP(S) 链接的文字到 Ash → 原有电脑/会话列表选择已有会话或新建 → 在原输入框编辑分享文案、补充要求 → 点击发送或创建。原有草稿按目标保留，分享原文不静默截断。首版只接受 text/plain、UTF-8 最多 32 KiB；不下载视频，不自动执行，不新增请求卡、收件箱或确认页。选择目标不触发模型任务；后续回复沿现有会话读取。以下请求卡及扩展材料体验仅在出现实际需求后增加，不作为本次链接分享前置条件。

### 用户体验

1. 用户在抖音系统分享中选择 Ash。Ash 保留来源链接、可取得的分享文字与采集时间，不声称已经获取完整视频。
2. 用户输入：“参考它的表达方式，结合我们的模板，制作一个介绍跨端协作的视频。”
3. Ash 展示短请求卡：参考内容、用户要求、目标电脑 / Codex / 默认项目。已有默认值时无需逐层选择；卡片上可修改。
4. 用户以“开始制作”提交，或用等价的明确自然语言授权。默认项目可以配置为用户指定的 `every_mission`，但不能仅凭名字相似自动绑定其他项目。
5. 电脑连接器创建会话；取得真实会话 ID 后，手机显示“已创建会话”，给出会话标题与所在项目。任务实际开始后才显示“处理中”。
6. Codex 按该项目已有 Mission Skills 和本地业务规则处理资料与制作。Ash 不决定视频生产阶段，也不生成第二套 Mission 对象。
7. 缺少素材、表达方向或需要用户判断时，问题回到这条协作记录。用户可以在手机回答或上传材料；答案发回同一会话。
8. 有结果时，Ash 展示回复和可领取产物；用户也能去电脑的同一会话继续。没有可用预览传输时显示实际可领取文件或打开位置，不伪装在线播放。

### 请求卡示意

```text
参考这条视频，制作我们的产品视频
来源：抖音链接 · 已保存分享文字
要求：参考表达方式，突出跨端协作

发送到：我的 Mac · Codex · every_mission  [更改]
方式：新建会话

[开始制作]  [仅保存]
```

示意内容不是最终视觉稿。默认项目为拟配置值；不代表已经为用户更改设置。

### 特殊情况

- 电脑离线：已可靠保存时显示“等待电脑”；仅手机本地保存时显示“待发送”。提供取消，说明是否会上线自动执行。
- 项目失效或缺少 Skill：显示具体缺项，不自动换目录、不暗中安装、不换成另一个运行器冒充原客户端。
- 分享内容读不到：保留已收到的来源，原会话可以继续根据可用信息判断或请求补充。
- 重复传输：按同一次提交的幂等标识去重。用户主动再做一个版本是新请求，不能因为来源 URL 相同被吞掉。
- Mission 本身已有手机采集与 start_case 交接设计：若复用其入口，只选择一条启动路径并关联回执，避免 Mission 和 Ash 各创建一次会话。

## 4. 场景 B：手机选择已有 Codex 会话并继续

用户可以从“电脑 → Codex → 项目 → 会话”查找，也可以直接说“继续昨天的产品视频”。已有明确绑定且没有歧义时直接定位；存在多个候选时展示少量标题、项目与最后更新时间，请用户选择。

会话列表优先显示原客户端标题和稳定 ID 对应的记录。初期可按工作目录名归组，完整路径在需要区分同名目录时展示；不冒充桌面完整项目结构。会话摘要按需读取并带来源时间，不在每次打开列表时读取全部聊天。

会话详情默认显示标题、消息和输入框。来源、材料、结果和发送记录按需打开；概括只在实际交接需要时提供。每次新要求在内部独立记录接收状态，异常时才提示，不把整段聊天标成“完成”。

原会话忙碌时，默认发送补充消息，不打断当前工具。已有桌面对照测试表明：追加消息进入同一轮，等待命令正常完成后，最终回复遵循追加要求。消息送达不代表正在运行的工具已采用新要求。若用户明确要求停止，必须走单独的停止能力；该能力尚未在 Ash 外部接入链验证。不能用独立进程返回的 notLoaded 或 interrupted 判断桌面真实状态。

会话已删除或不可续接：明确告知，并允许用户将获准的局部背景带入新会话。新旧会话保留关联，不能静默替换目标。

## 5. 场景 C：电脑向手机请求局部帮助（后续阶段）

2026-10-12 用户明确选择“先交付已有功能，主动索取材料延期”。原会话通过工具主动请求手机材料、按请求 ID 回取的 machine-callable 能力移至后续，不再作为本次首阶段退出条件。保留以下目标与技术限制，不将已有对话补材冒充该能力完成。用户主动分享链接、选图发送到原会话以及结果回收仍属首阶段。

例如 Codex 需要手机后台截图或现场照片，由原会话通过接入工具发起请求。手机显示所需材料和用途，用户提交后，原会话按请求 ID 取回结果。

这一方向与手机发起共用身份、请求、上下文、附件和回复关联。是否拆分任务由发起端决定，不要求 Ash 理解完整视频工作流。首次允许人工选图；自动操控手机 App 是另一项按能力验证的扩展。

历史上该场景列为首版双向验证目标；依据用户 2026-10-12 的选择，现延期至后续。后续实现若原会话无法自动唤醒，先支持下一轮查询，不把被动保存结果说成已回到原会话。

## 6. 手机产品结构

### 首页：最近协作与需要我处理

顶部提供自然语言输入和分享材料入口；下方优先展示需要回答的问题、最近发出的请求及新结果。用户无需同时维护“任务系统”和“消息收件箱”。底层收件记录服务于这些入口。

每张卡片说明：这次做什么、交给哪个客户端、最后确认到哪一步、是否需要用户处理。技术错误展开后才展示详细信息。

### 会话浏览

选择电脑与客户端后浏览其会话，支持项目或目录筛选、标题搜索、最近使用。会话读取权限与执行权限分开；连接器没有某项能力时，界面说明范围。

### 协作详情

围绕一次发起或一个关联会话展示请求、回复、材料、待回答问题与结果。不复制桌面客户端完整界面，不强制同步全部消息和思考过程。可将新要求继续发往绑定会话。

### 连接与默认值

管理电脑、客户端、授权范围，以及可修改的默认新建项目。会话列表按用户授权范围同步。撤销连接后停止后续访问，说明已传出的文件副本不能自动收回。

## 7. 最小对象与上下文

首版只引入通用协作对象：

| 对象 | 保存什么 | 边界 |
| --- | --- | --- |
| 连接 | 用户拥有的设备、客户端、已验证能力与授权 | 在线不等于可执行所有操作 |
| 工作引用 | 来源执行端、原生对象类型与 ID、目录 / 项目映射、标题与更新时间 | 可以引用聊天会话或云作业，不复制源系统业务状态机 |
| 请求 | 用户意图、目标、必要背景、输入、有效期限与回执 | 一次请求可以只是局部协作，不等于完整业务任务 |
| 材料与结果 | 来源、文件或授权引用、版本、摘要与返回关联 | 返回结果不等于业务验收通过 |

“事情”可作为多个会话与请求的可选关联视图，首版不要求用户先创建事情、任务树或工作流。

新建会话提供：用户原话、来源材料、选定项目及必要的用户背景。继续会话主要提供本次增量；先复用原会话上下文，不再覆盖一份由 Ash 猜测的完整历史。

跨客户端交接时才准备可独立理解的短背景：目标、已确认决定、现有结果、这次需要什么、未确定部分及来源。来自不同 Agent 的结论保留各自来源，不能自动合成用户决定。

用户长期背景、项目背景和本次材料分别限定使用范围。缺少某段历史可以明确说明并请接收端补问，不以补齐所有数据为产品前提。

## 8. 状态、通知与授权

内部可区分的请求状态包括：待发送、等待电脑、已接收、处理中、需要你、已返回、未完成、结果待核实、已取消 / 已过期。具体状态以可证明事件为依据，连接能力不足时不猜测。

电脑联网不是接收回执；取得 thread_id 不是执行完成；模型说完成不是文件已传到手机；已有输出不是用户验收通过。需要展示状态时，只显示影响用户下一步的简短结论；最后确认时间与证据按需查看。

默认采用按需同步：Ash 关闭时不要求同步或推送桌面会话消息；打开时刷新列表，进入会话时读取最近消息。正在查看的会话可以有界刷新，离开后停止刷新。完成提醒等主动通知作为以后可选能力，不列为首版必需。

用户明确的制作请求足以启动授权范围内的工作，不层层重复确认。发布、对外发送等后续动作继续服从对应业务规则与已有授权；“制作视频”不会自动变成“发布视频”。手机回复须关联具体问题、版本和原会话，不能把普通一句“可以”匹配到所有待确认动作。

连接器必须如实声明执行环境权限。现有 Ash Codex 运行器使用全访问配置，不能因请求卡写了范围就宣称操作已隔离。权限问题需要实现和验证，不靠增加笼统确认按钮解决。

## 9. 技术方案与已知事实

目标结构：入口端 → 已认证的跨端通道与请求记录 → 电脑连接器 → 原客户端支持的会话接口；事件与结果沿关联链返回。调用者可以来自任何端，通信服务不负责统一决定业务流程。

优先复用 Ash 已有核心消息路由、ledger、client_id 去重与 reply_to。核心本地 MCP 与桌面运行器私有 MCP 的权限和生命周期不同，外部身份不能伪装成本地 owner。是否需要新增持久队列，应先映射现有超时、恢复与投递能力，不从零复制一套消息系统。

| 能力 | 当前证据 | 产品处理 |
| --- | --- | --- |
| 外部程序读取本机 Codex 已有会话 | 独立 app-server 的 thread/list 实测两页 103 条记录、71 个不同 ID，分页耗尽 | 可以推进会话选择器接入；需要去重，不能外推全部云端或归档会话 |
| 会话标题、ID、工作目录 | 实测匹配 ash、cvmax-autofill、itsallsame 等既有会话 | 可用于定位和初步目录归组 |
| 项目归属 | App Server 抽查 projectId 为空；本地 .codex-global-state.json 找到当前会话的项目归属 | 有只读补充来源，需版本兼容，不直接依赖它实现完整侧栏镜像 |
| 桌面实时运行状态 | 独立接口对活跃会话返回 notLoaded，轮次也可能显示 interrupted | 只能把它作为历史读取源，不能据此显示桌面已停止 |
| Ash 托管 Codex 新建 / 续接 | 已有 thread/start、thread/resume、turn/start 等代码 | 不是指定桌面项目正确归组及既有活跃会话续接的验证 |
| 指定项目新会话在桌面可见 | 用户确认 itsallsame 已验证 | 作为已有前提，复用原路径，不重复列为研究阻塞 |
| 分页读取已保存消息 | thread/read 读到当前会话 75 轮；thread/turns/list 读到当轮用户消息、开场回复及之前完整问答，两页无重复 | 支持打开时取最新、上滑加载历史；不保证未落盘内容实时可见 |
| 独立 App Server 追加运行中桌面会话 | turn/steer 返回 thread not found | 该直接路径本次失败；不能通过另起执行进程悄悄代替 |
| 桌面内置发送工具追加运行中会话 | 独立测试会话执行一次 45 秒等待，同轮最终回复包含追加标记 | 桌面本身支持追加；外部 Ash 如何取得该控制入口仍是核心缺口 |
| 手机问题回传、附件到达、跨重启恢复 | 尚未完成完整验证 | 首版必须做闭环及故障验证 |

证据分三次取得：会话列表与消息读取为只读验证；用户另行授权了独立模拟会话，进行了等待与追加对照测试。未向业务会话发送测试指令。重复会话记录的来源仍待查明。测试会话 ID：01a11f8f-7ff8-7ab2-9ad7-0607832213a9；追加消息进入同一 turn，等待命令只执行一次、退出码为 0，最终输出 TEST-BASE-DONE ASH-APPEND-OK。本测试不能证明任意工具的精确中途处理时机。

## 10. 首版范围与验收顺序

首版面向一位用户、一部手机、一台电脑、Codex。产品范围包含手机新建工作、选择已有会话继续、查看结果与补充材料；默认项目可配置，离线与未知状态可理解。用户主动分享链接、发送图片与结果回收仍需闭环；电脑原会话 machine-callable 主动索取手机材料按用户 2026-10-12 决定延期。

按以下顺序研究和验收，不以新增功能数衡量进展：

1. **会话发现。** 稳定列出目标范围、去重、建立目录与项目映射，确认用户能找到指定会话。
2. **按需读取。** 复用已验证的 App Server 历史接口，设计最近页刷新、消息去重、在途消息更新和离线展示。指定项目新建复用 itsallsame 已验证的路径。
3. **外部控制接入。** 找到 Ash 电脑连接器能够调用的桌面会话控制通道。桌面内部工具成功不是外部可调用的证明；明确处理中追加、空闲开始下一轮及发送结果未知的行为。
4. **真实局部闭环。** 手机分享一个参考链接，Codex 使用现有业务流程处理；需要用户补充时能在手机回复。业务成功由其原流程验收，Ash 单独验收交接成功。
5. **断线与重复。** 提交后丢回执、创建会话后进程中断、手机离线、附件领取失败；恢复后定位同一请求和会话，不能盲目新建或重复执行。
6. **用户主动补材与结果回收。** 用户主动分享链接或选择图片发送到明确目标，原会话接收；回复和获准结果文件可在手机查看或领取。原列“电脑主动请求手机”按用户 2026-10-12 选择移至后续，见第 5 节。

后续再接第二种客户端，验证协议是否真能复用。多 Agent 并行、自动按价格分派、完整个人记忆、全平台发布、任意客户端接管不进入首版。对仅能手动交接的工具明确标示，不能把“支持复制”宣传为“已连接执行”。

## 11. 成功标准与关键风险

业务价值观察：从手机看到材料到电脑正确开始工作的步骤与耗时；用户重复解释背景的次数；回到电脑时是否找到同一会话；需要回答的问题是否能在手机处理；结果是否能从发起入口找到。与当前复制链接、找会话、重述要求的路径比较，先测基线再设数值目标。

可靠性硬条件：不能投递错会话；重复传输不自动开启第二次工作；不以未知状态冒充成功；授权材料不能被其他连接领取；不存在的文件不能显示已交付。

最大技术风险是“读取历史”和“控制桌面会话”不是同一能力。若只能读列表、只能另起独立运行器，应停止承诺原会话遥控，明确展示已验证的能力，再研究合适接入方式。指定项目新建已由用户确认，不再重复验证。

最大产品风险是引入另一个需要维护的收件箱。解决方向是原入口直接可见请求和结果、默认目标减少操作、后台关联技术记录。若实际步骤仍多于分享与复制，必须收缩或调整方案。

## 12. 对五轮对垒的继承与修正

- 继承三种意图、局部上下文、有来源的快照、人工与自动共存、未知状态不重做等裁决。
- 首个价值场景由合成周报转为用户明确提出的手机内容 → Codex / Mission 制作；合成场景仍可用于故障测试。
- 新建会话是用户明确需要的独立场景，因此属于正式能力；不能用它冒充对已有会话的续接。
- 会话发现和历史消息读取已取得外部实测证据；桌面内部追加成功，独立 App Server 直接追加失败，Ash 外部控制入口待研究。
- 手机发起与电脑发起都保留，业务编排留在 itsallsame 等消费者项目，Ash 不成为必经的业务决策中心。
- 本轮仅完善设计，纳入此前获准的模拟测试结果；未开发功能、运行内容生产业务或重新开展 Agent 对垒。


## 13. 按需同步与消息发送契约

### 打开手机时的行为

1. 先展示手机已有缓存，并标明上次同步时间；缓存不冒充最新内容。
2. 电脑可连接时读取会话列表。选中会话后，使用 thread/turns/list 获取最近轮次及完整消息；向上滚动时使用分页游标加载更早内容。
3. 当前页可采用约 3–5 秒的初始刷新间隔，作为待测参数；页面不可见即停止。失败时退避，手动刷新可重试。无需订阅所有桌面会话，也无需后台持续上传全部历史。
4. 按连接 / 主机、会话、轮次及消息 ID 合并。近期轮次反复读取，更新同一条消息，不只追加新 ID。分页游标只用于分页，不能假定它是更新事件游标。
5. 更新期间保留用户滚动位置；正在看旧消息时显示“有新消息”，不强行滚到底部。

电脑离线时显示“电脑未连接，以下为上次同步内容”。首次访问且没有缓存时明确无法获取历史。电脑关机后仍可读到关机前全部最新消息，需要额外后台备份，本版不承诺。

### 从手机发送消息

手机先生成 client_message_id，展示本地待发送消息。电脑连接器确认目标与权限后，通过已验证的控制入口提交；取得对应回执后改为“已送达”。还没有外部控制入口时，界面不能显示成功或自动退回到创建新会话。

刷新读到同一条原会话消息后，将本地待发送记录与它合并。优先使用目标接口返回的稳定 ID 或明确关联字段；没有对应能力时保留“待核对”，不能仅按文本相同强行合并或据此去重执行。

用户侧措辞区分：

| 情况 | 展示 |
| --- | --- |
| 消息仍在手机 | 待发送 |
| 连接器已记录，但未确认进入 Codex | 等待送达 |
| 控制入口确认接收 | 已送达 |
| 已送达，但原工具仍在执行 | 补充消息已送达；处理时机由 Codex 决定 |
| 接收结果因断线不明 | 送达状态待核实 |

“已送达”不承诺最终执行或业务完成。回执丢失时先查询和核对，不能自动重复提交。手机取消尚未投递的消息可阻止发送；已送达的消息不提供虚假的撤回保证。

### 运行中追加与停止

默认补充消息沿用 Codex 的处理节奏，不终止当前工具、不创建另一个执行者。已观察到同轮最终回复遵循追加要求；不承诺即时修改已经启动的 shell 命令、上传或其他外部动作。

“停止当前任务”是独立控制操作。首版仅在连接器验证支持后开放，并等待实际停止回执；界面点击成功不能代替执行已停止。用户明确说“等结束后再做”的顺序要求，也必须由连接器能力落实，不能简单把它作为当前轮追加文本后宣称已排队。

### 消息与业务边界

默认同步用户消息、助手可见回复、明确待答问题及产物引用；工具详情可按需展开，不同步内部推理作为聊天正文。授权或待答问题必须保留来源问题 ID 与有效性；单纯从历史读取到问题，不代表它仍在等待答案或 Ash 已有审批能力。

文字中的电脑路径只是产物位置。文件预览与下载需单独授权传输，未交付时显示“文件在电脑上”，不能显示手机已收到。

桌面直接新增消息在手机下一次读取时出现；Ash 发出的消息通过目标接口进入原会话后，同样由历史读取确认。跨时间上下文由原会话历史和必要增量承接，Ash 的缓存是读取副本。

## 14. 当前研究重心

已经确认：指定项目新建会话（用户确认）、外部列会话与分页读消息（本机实测）、桌面内部运行中追加（隔离模拟实测）。

下一项研究仅聚焦：电脑端 Ash 如何访问拥有该活跃会话的控制入口，取得发送回执并建立消息关联。不要把读取数据库、另启 App Server 或内部工具可用分别夸大为外部控制链已完成。不需要为本阶段先设计所有会话的实时订阅。


## 15. 多端产品模型：位置、执行端、工作

“在哪里”和“交给谁”分别表达。一个位置可以有多个执行端，同一种客户端也可以出现在不同位置。执行端指一个具体安装实例或服务连接，不只是品牌名称。

| 层次 | 示例 | 作用 |
| --- | --- | --- |
| 位置 | 我的 Mac、办公 Windows、云服务器、红米手机 | 表明材料和执行环境所在位置 |
| 执行端 | Mac 上的 Codex、Windows 上的 Codex、Mac 上的 Claude / WorkBuddy / Kimi、云采集服务 | 提供经过核实的能力和独立授权 |
| 工作范围 | 项目、工作目录、服务工作区 | 保持执行范围；没有该概念的服务无需伪造项目 |
| 工作 | 已有聊天会话、新会话、渲染作业、一次服务调用 | 原生对象由执行端拥有，Ash 保存引用与关联 |

上述品牌均为目标覆盖举例，并未验证各版本接口；Mac 的验证结果不能外推 Windows，同品牌 CLI 与桌面客户端也不能视为同一实例。

用户交互：默认目标是一条可修改的完整绑定，如“我的 Mac / Codex / every_mission”。存在同名项目时按实际位置区分，不能仅凭名称或目录尾部合并。手机端目标选择器先展示最近和常用目标，再展开完整位置 / 执行端列表。用户可以直接说“交给 Windows 上的 Codex”，不必理解内部 ID。

已有工作显示来源标签，如“Mac · Claude”或“云服务器 · 渲染服务”。点击后按原生对象显示聊天记录或作业结果；统一的协作页面不要求所有对象都变成聊天。

## 16. 扩展场景与上下文交接

### 云服务提供局部结果

Codex 或用户请求云采集服务收集指定资料，服务返回作业 ID，发起端以后按需查询。结果保留来源、采集时间与未完成部分。电脑取得结果后继续原业务，手机无需在线。云端是执行方而非所有业务的总调度者。

若服务支持同步调用，直接记录一次请求和结果即可，不强建长期作业或 Agent 会话。若用户明确要求定时或长期任务，由具备调度能力的服务承担；Ash 记录关联和结果位置，不因为接入云服务器就新增一套业务调度系统。

### Windows 与 Mac 的资源互补

用户在手机要求 Windows 上的 Codex 处理仅在 Windows 可用的项目或软件，之后让 Mac 上的另一个工具审阅结果。项目路径保留为各端原生路径，不能把 Mac 路径原样交给 Windows；需要交付的材料必须实际可达。

若 Windows 离线，显示等待或无法投递；不能自动改派到 Mac 并假设软件、资料与授权相同。云文件链接、本地副本或限定文件传输都可以是材料交付方式，但必须核对目标端确实可读。

### 多种 AI 工具分工

用户可明确指定 Codex 做分析、WorkBuddy 做一项执行、Claude 或 Kimi 审阅。拆分可以来自用户或任意已接入 Agent；Ash 提供通用交接，不强制建立任务树，也不默认递归转派。

跨工具发送的是本次需要的背景包：目标、已确认决定、现有材料和版本、本次要求、期望产出、授权范围、来源及缺失信息。接收方在自己的工作里处理。原工具的完整上下文、登录状态、工具权限、模型隐含状态不会随摘要迁移。

并行评估时分别保存各方结果和来源，汇总方由发起者指定或自己承担；不能让最后返回的答案自动覆盖其他结论。涉及共享文件写入时必须明确产物或工作区边界，未具备协调能力的连接不能默认并行修改同一目录。

### 既有会话的转交

“让 Claude 看一下 Codex 的方案”通常创建一个关联的审阅工作，结果返回原请求；它不是把 Codex 会话改成 Claude 会话。用户可选择继续在 Claude 工作，但来源和分支关系保留。实际新建、发送能力不足时提供明确的人工交接，不显示自动派工成功。

## 17. 能力协商与连接器边界

每个具体执行端独立声明能力，不能只显示一个“已连接”标签。展示“可读会话、可新建、可追加”等用户能理解的范围；内部记录接口版本、最近验证时间及失败原因。

| 能力 | 产品行为 | 不支持时 |
| --- | --- | --- |
| 发现工作范围与已有工作 | 浏览项目、会话或作业 | 使用明确目标或人工选择，不伪造目录 |
| 读取历史与结果 | 按需加载内容和状态 | 显示最后快照与来源，不宣称最新 |
| 创建工作 / 调用服务 | 发起新会话或提交作业 | 只准备材料或人工交接 |
| 给已有工作发送输入 | 在原会话补充要求 | 不擅自创建替代会话 |
| 运行中追加 | 按原端规则处理补充消息 | 明确不支持；只有具备排队能力才显示等待下一轮 |
| 回答问题 / 审批 | 将回答绑定原问题或审批请求 | 引导到原端操作，不以普通文本冒充批准 |
| 停止 | 请求取消，并查询实际结果 | 明确无法远程停止 |
| 附件传输 | 获准材料在接收端可读 | 显示仅有引用或尚未交付 |

身份与权限按执行端区分；配对一台电脑不自动授权读取该电脑全部客户端、历史和文件。云服务使用自己的凭据与作用域，原始凭据不进入背景包。客户端普通命令行可用，也不证明可以控制其桌面当前会话。

协议候选操作为 discover、list_work、read_work、create_work / invoke、send_input、get_result、cancel、transfer_asset。它们是概念契约，不是本次已实现接口。连接器按支持的子集接入，保留原生信息，不要求云服务实现聊天专有操作。

## 18. 跨端一致性与结果归属

每次交接保留全局 request_id、原始输入 ID、目标执行端、原生工作引用、来源工作引用和返回位置。原生工作引用至少由连接身份、执行端实例、对象类型与原生 ID 联合定位，不能只用品牌名或裸 thread_id。

原系统是工作内容与执行状态的来源；Ash 保存交接记录、获准的缓存和可追溯摘要。相同消息跨端显示时依原生 ID 与映射合并。不同端的时钟不能决定谁的结论正确或哪个授权有效。

按需同步是通用默认：查看哪个执行端、哪项工作，就读取相应最新记录。订阅事件是可选加速方式，不能成为所有连接器的门槛。对只能返回最终结果的服务，展示处理中和最终结果，不模拟流式聊天。

首次发起就记录结果返回位置。默认回到原请求，原会话能接收时可以回写；不能接收时只在关联记录提供领取入口，不显示“已回写原会话”。原会话被删除时保留已有授权范围内的协作记录，允许用户选择新的接收位置。源端不可达时显示同步时间与可用缓存范围。

工作状态与消息传递状态分开保存：服务完成作业但附件尚未传回，可以显示“处理完成，文件待领取”；发送者离线不等于作业暂停。源端的未知状态不能通过另一个客户端的推测抹除。

设备连接失败、授权撤销、能力版本变化时，暂停受影响的投递，保留未完成事实；不自动改派到其他模型或设备。用户明确授权可替代目标时也需重新核对材料访问和动作范围，不能继承另一个执行端的全部权限。

## 19. 扩展路线与验收

架构从现在按多端设计，实现按已验证价值推进：

1. **手机 ↔ Mac Codex。** 当前首个闭环：默认项目新建、已有会话读取、外部发送入口、按需补齐消息、材料交付。
2. **第二个桌面执行端。** 根据用户真实使用频率选择 Windows Codex 或 Mac 上的另一客户端，证明位置和客户端可以独立适配；不预设所有品牌接口都可用。
3. **一种云服务。** 选择有明确请求 / 结果契约的局部服务，验证非聊天作业、异步领取、电脑离线时的真实运行状态。
4. **用户指定的跨工具分工。** 验证从一个已有工作交接局部要求到另一个执行端，结果回到来源；之后再研究自动选择、成本优化和更复杂并行。

每个连接器需记录已支持动作、操作系统 / 客户端版本、权限、离线行为、重复提交行为、结果回收和人工步骤。某一客户端不支持的动作只影响该连接，不能拖累整体协议或偷偷扩大执行方式。

扩展成功的检验是：接入第二个端不需要重写手机业务界面或新增视频生产状态；云作业能自然显示；同名会话不投递错；转交后少重复解释；结果能够找到来源。AI 工具费用或“免费额度”仅在来源可核实时展示，不默认把便宜工具作为自动分派理由。


## 20. 普通用户从零开始

### 默认路径：托管连接服务

目标体验是“两端安装 → 一次配对 → 选择工具和默认项目 → 第一条请求”。这是产品化目标，当前实现尚未完成全流程验收。用户无需自行搭网关、安装 Node.js、填写端口或复制令牌。

1. 手机安装 Ash，进入“连接电脑”。首次只解释手机与电脑分别承担什么，不要求配置云 Agent 或所有客户端。
2. 电脑安装 Ash 连接助手。助手显示一次性配对码或二维码，手机扫码；电脑与手机显示可辨认的设备名称，用户确认连接及访问范围。
3. 助手检测本机可接入的客户端，区分“已安装”“需要登录”“可读取”“可发送”。用户选择 Codex 等目标，继续使用该客户端原有登录；检测不到时提供安装或打开客户端的引导，不声称自动获得账号。
4. 用户选择允许访问的项目或会话范围，以及默认新建项目。范围可在以后修改，不默认开放所有历史和文件。
5. 执行无业务副作用的连接检查：读取允许范围内的列表、确认版本和控制能力。读取通过而发送不可用时明确标记，不展示全部就绪。
6. 手机展示“电脑已连接，可以开始”。用户主动输入或分享第一条要求才创建实际工作，不在安装向导里自动跑模型任务。

首版优先复用现有设备配对机制，产品账号不是额外强制依赖。若以后加入同账号设备发现，仍需明确设备绑定及授权；登录同账号不自动授予所有项目访问。配对码应一次性、短期有效，失败和过期时可重新生成。

### 电脑连接助手

助手以 macOS 菜单栏或 Windows 系统托盘程序为目标形态，负责连接状态、客户端检测、权限管理、诊断、更新与退出。运行时与必要依赖随安装包提供，普通用户不操作 CLI；服务器安装保留管理员 CLI 路径。

用户可以选择登录系统后自动启动。界面明确区别“关闭设置窗口”和“退出助手”：退出后手机无法继续访问本机。电脑休眠、关机、断网时展示不可达及最后同步时间，不假装电脑工作仍可执行。不默认阻止系统休眠。

安装手机 App 与电脑助手是两个设备各自的入口；手机采集和协作尽量集中在 Ash 内，不要求为普通协作再安装第二个配套手机 App。特定业务已有独立 App 时允许复用，但不能把它变成通用协作的必装项。

### 首次使用失败时

| 情况 | 用户看到与下一步 |
| --- | --- |
| 电脑未安装助手 | 展示对应系统的安装入口与简短步骤 |
| 配对码过期 | 重新生成，不要求用户处理密钥 |
| 客户端未安装或未登录 | 指向原客户端完成准备，再重新检测 |
| 只能读取，无法发送 | 明确能力限制，允许浏览，不显示可远程执行 |
| 默认项目不存在 | 选择现有项目，不擅自新建或换目录 |
| 系统权限不足 | 只解释当前动作实际需要的权限，提供系统设置入口 |
| 网关或网络不可达 | 保留本地输入、展示连接检查与重试，不要求重新配置全部环境 |

不要把内部接口名、进程 epoch、数据库错误作为普通用户的主提示。诊断详情可展开或导出，默认排除聊天正文和凭据。

## 21. 托管与自托管的产品边界

| 方式 | 普通用户工作 | 运营责任 |
| --- | --- | --- |
| 默认托管 | 安装两端、配对、选工具与范围 | 我们提供连接网关、证书、服务监控与升级兼容 |
| 自托管 | 管理员部署网关；终端用户扫描配置入口后配对 | 管理员负责域名、HTTPS、持久存储、备份、可用性与服务端升级 |

托管服务默认承担通信，不等于把用户的 AI 模型调用、全部聊天或文件都上传到我们的服务器。哪些数据经过中继、哪些会保存及保存多久应在连接设置中明确；未实现端到端加密时不得宣传中继无法读取内容。

自托管属于高级部署选项，普通用户无需理解。更换网关涉及信任和设备绑定变化，不能静默迁移凭据、历史和权限。管理员可以提供统一配置入口，但设备仍需建立有效授权。

一台电脑、一个客户端足以完成首次使用。更多电脑、云服务及其他 AI 工具在“添加连接”中逐个接入，不进入首次安装的必经流程。用户原有客户端费用与可能的连接服务费用分开说明，定价尚未决定，不承诺所有工具免费。

### 离线预期

操作本机客户端需要电脑在线且助手可用。手机可读已有缓存；没有后台持久信箱时，尚未交付的请求只能等发起端恢复运行后重试。若未来提供“手机关闭后，电脑上线自动执行”，必须以服务端可靠接收、目标授权与恢复机制为前提，并单独验收。

### 易用性验收

从干净的受支持电脑开始，普通用户无需终端或人工复制令牌，能完成安装、配对、选择已有项目和发送第一条明确请求；手机和电脑都能定位同一工作。另验收休眠后恢复、助手重启、升级失败与撤销连接的提示是否可理解。首轮测量实际步骤、耗时与失败点，再确定量化目标，不先承诺安装所需分钟数。

## 2026-10-11：未发送文字的最小恢复

已有会话与新建页沿用原输入框。未发送文字、已接收但尚未选目标的分享，保存在手机本地，退出重开后在同一授权范围及同一会话/项目恢复；本地草稿记录闲置 24 小时后过期，容量有界。恢复不发送、不新建，也不增加草稿列表、设置或常驻说明。分享在可靠本地保存后才确认接收；切换会话不覆盖原草稿，已送达内容不再作为新草稿回填。存储异常时保留当前原文并给出短提示，后台保存不改变焦点、候选字或选区。

新建请求的正文在可靠保存到既有本地创建记录后才离开输入框。创建失败或状态待确认时，在该记录原有详情内只读保留原文；核查沿原操作进行，不把未知提交恢复成可重复创建的新草稿。创建、标题和首条消息均被确认接收后清理正文副本。既有无正文记录保持兼容，不增加第二本投递账本。

## 2026-10-11：已有会话的最小图片入口

输入框旁提供“图片”，直接打开系统单选 PNG/JPEG（最多 4 MiB）。返回同一会话只显示文件名与移除按钮，要求仍写在原输入框，由原发送按钮发送文字与图片。选图不执行，不进入第二个材料表单，不显示正常协议说明、保存/partial/来源 ID/回执等工程信息。传输失败保留内容，不降级成只发文字。状态未知沿原操作查询；切会话或授权改变不得串图。先交付一张图到已有会话，暂缓多图、新建带图、缩略图和系统图片分享。

图片接收沿连接器当前精确会话 receive_input 范围；文字控制授权不自动扩为文件接收。必要授权一次说明选定会话和用户主动选择的材料，再验收实际图片内容和手机回复。


### 重启后的读取恢复

正常电脑重启、连接器重启或 Codex 普通配置改写，不应要求重新配对或重新授权同一读取范围。软件重新验证原来源与账号后恢复；账号、已确认的来源目录或授权范围实际改变时才要求确认。长期授权与当前文件/进程校验分离，旧读取进程和旧结果仍按变化失效，不自动接受新来源或扩大范围。读取不可用时显示事实状态，不以“请先连接电脑”冒充配对丢失。
